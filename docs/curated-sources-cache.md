# 策展来源与后台缓存

本次在既有 Provider 协议上增加 Behance 和 FilmGrab，保持浏览下载节点无输出端口。

## 职责划分

- `BehanceProjects` 读取公开 GraphQL 项目连接和真实游标；`BehanceClient` 读取项目图片；`BehanceProvider` 负责素材标准化。图集只接受文件名包含当前项目 ID 的模块图，排除推荐项目。
- `FilmGrabClient` 读取 WordPress API；`FilmGrabProvider` 解析图库链接，按电影 ID 与静帧 ID 建立稳定标识。每页24张，游标包含电影页码和帧偏移。
- `FilmGrabArticles` 独立管理电影文章缓存：5分钟内翻页复用，刷新强制访问来源，请求失败时回退已保存的文章并标记过期结果。
- `CuratedDownloader` 处理域名、大小、图片格式校验及原子写入。
- `AssetIndex` 只负责图片文件和 SQLite 索引，键为来源、站点、素材 ID。
- `CacheJobService` 只负责后台遍历、去重、进度和取消。搜索、详情、下载仍由原有用例负责。
- `CacheProgress` 按来源、搜索词与筛选条件独立持久化遍历断点，达到单次目标时保留当前页以便下次处理剩余素材。
- `film_catalog` 独立维护中文片名、别名、画面风格与已核实的 FilmGrab 电影 ID；片单通过来源描述符交给通用控件渲染。
- 缓存入口由 Provider 的 `cache` 能力声明驱动，前端与任务服务不需要各自维护来源名称列表。

## 缓存语义

“新增缓存100张”首次从当前搜索的第一页开始，之后从该搜索条件的断点继续。最多新增100张卡片预览和对应详情（包含公开提示词、负向提示词及工作流元数据）。已有缓存跳过且不计入新增数量；失败项计数后继续，来源耗尽时按实际数量完成并清除断点。单次最多扫描50页或500个不同素材，达到上限时保留断点，下次点击继续，防止持续失败导致无限任务。

文件与索引保存在 `output/ty-node/ty-image-spider/cache/`。索引跨 ComfyUI 重启保留；运行中的任务在进程退出后停止。切换来源不会停止任务。取消会在当前网络请求返回后生效。

搜索命中索引时复用本地预览和详情。Civitai 在提示词筛选前查询索引，避免重复请求详情。明确点击下载仍获取来源原图，缓存预览不会冒充原图。普通本地历史排除后台缓存目录。

## 来源边界

- Behance 精选画廊与全站关键词搜索均使用真实分页，每页24项。空关键词时使用选择的精选画廊。关键词搜索排序由来源决定，跨页少量重复由缓存任务去重。
- FilmGrab 支持连续静帧分页，内置24部中文片单与常用别名；匹配已收录片名时按电影 ID 查询，避免短片名被全文搜索误匹配。片单以外的中文名通过可选 TMDB 资料查询、身份确认与持久映射接入，详见 [中文电影查询](tmdb-movie-mapping.md)；其他英文关键词保留普通搜索，也可点击“查找电影版本”做身份查询；留空浏览全部电影。
- 小红书仍保留原有 OpenCLI 流程。本次批量缓存不支持小红书，避免保存签名链接；本地历史本身已在磁盘上，也无需后台缓存。
- 多图项目每项缓存一张预览，其他原图在查看时联网加载。
